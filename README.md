# Сайт сбора для Бони — инструкция

Это готовый сайт. Он работает на бесплатном хостинге GitHub Pages: без админки, базы данных и сервера. Всё, что меняется (суммы, чеки, новости, реквизиты), хранится в одном файле — `content.json`. Сайт сам пересчитывает все итоги по этому файлу.

Адрес сайта после публикации: **https://elenabuteeva.github.io/bonya/**

## 1. Что лежит в архиве

```
bonya/
├── index.html       ← сама страница (менять не нужно)
├── content.json     ← ВСЕ данные сайта: тексты, суммы, чеки, новости, реквизиты
├── README.md        ← эта инструкция
├── .nojekyll        ← служебный пустой файл для GitHub Pages (не удалять)
├── assets/          ← оформление и программа сайта (менять не нужно)
│   ├── style.css
│   ├── app.js
│   ├── qr.js        ← рисует QR-коды прямо на сайте
│   └── favicon.svg  ← значок вкладки (пиксельный котик)
├── photos/          ← фотографии Бони
├── receipts/        ← сюда кладёте чеки
└── documents/       ← сюда кладёте выписки, заключения, анализы
```

Всё, что вы будете менять в обычной жизни, — это **`content.json`** и файлы в папках **`photos/`**, **`receipts/`** и **`documents/`**.

> Файл `.nojekyll` начинается с точки, поэтому на компьютере он может быть скрыт. Если при загрузке он потеряется, ничего страшного: сайт будет работать и без него.

## 2. Перед публикацией: важно про личные данные

**Репозиторий на GitHub будет публичным.** Любой человек сможет открыть любой файл, который вы туда загрузите, — и `content.json`, и все чеки, и выписки.

**GitHub хранит историю всех изменений.** Если вы загрузите выписку с адресом, а потом удалите её, старая версия всё равно останется в истории, и её можно найти. Поэтому:

- загружайте **только копии, в которых личные данные уже закрыты**;
- никогда не загружайте оригиналы «на время».

**Что закрывать в выписках и чеках:**

- ФИО владельца (в ваших выписках это «Бутеева Елена Владиславовна», а в документах клиники «БЭСТ» ещё и «Бутеева Ольга Федоровна»);
- домашний адрес;
- ваши личные телефоны (в шапке результатов клиники «БЭСТ»);
- номер карты, если он виден на чеке (можно оставить последние 4 цифры);
- всё, что вы не хотите показывать посторонним.

Адреса и телефоны клиник, кличку, возраст и породу Бони можно оставить. Имена врачей — на ваше усмотрение.

**Как закрывать правильно.** Ваши PDF сняты айфоном, внутри них — фотографии страниц. Если в редакторе PDF просто нарисовать чёрный прямоугольник поверх текста, под ним может остаться исходная картинка. Надёжнее так:

1. Откройте страницу как картинку (или сделайте скриншот страницы).
2. Закрасьте личные данные сплошным цветом в любом редакторе фото (на айфоне: «Фото» → «Править» → значок разметки → маркер или прямоугольник с заливкой).
3. Сохраните результат **как новую картинку** (JPG) — тогда под закрашенным ничего не останется.
4. Проверьте: увеличьте картинку и убедитесь, что ничего не читается.

Картинки (JPG) на сайте открываются прямо на странице — крупно, с увеличением. PDF открываются в новой вкладке. Для телефонов удобнее JPG весом до 1 МБ.

> Если хотите, пришлите Claude оригиналы — он подготовит закрытые и облегчённые копии с правильными названиями. Вы их проверите и загрузите сами.

**Названия файлов** — только латиницей, без пробелов, строчными буквами. Удобная схема: `год-месяц-день-что.jpg`, например:

- `receipts/2026-09-27-chek-1.jpg`
- `documents/2026-09-27-vypiska.jpg`

## 3. Публикация на GitHub шаг за шагом

### Шаг 1. Войдите в GitHub

Откройте https://github.com и войдите в свой аккаунт **Elenabuteeva**.

### Шаг 2. Создайте репозиторий

1. Справа вверху нажмите **«+»** → **New repository**.
2. **Repository name**: `bonya` — именно так, маленькими латинскими буквами. От этого названия зависит адрес сайта.
3. **Description** (необязательно): `Сбор на лечение Бони`.
4. Выберите **Public** (публичный). На бесплатном тарифе GitHub Pages работает только с публичными репозиториями.
5. Галочки «Add a README», «.gitignore», «license» **не ставьте**.
6. Нажмите **Create repository**.

### Шаг 3. Загрузите файлы

1. Распакуйте архив `bonya.zip` на компьютере. Получится папка `bonya`.
2. На странице нового репозитория найдите ссылку **uploading an existing file** (или кнопку **Add file → Upload files**).
3. Откройте папку `bonya` на компьютере, **выделите всё её содержимое** (файлы `index.html`, `content.json`, `README.md` и папки `assets`, `photos`, `receipts`, `documents`) и перетащите в окно браузера.
   - Перетаскивайте именно **содержимое** папки, а не саму папку `bonya` и не zip-архив. На GitHub файл `index.html` должен лежать в самом верху, рядом с `content.json`.
   - Перетаскивание папок работает в Chrome, Edge, Firefox и Safari. Если папки не перетаскиваются — загрузите их по очереди (см. ниже «Как загрузить файл в папку»).
4. Дождитесь, пока все файлы появятся в списке.
5. Внизу, в поле **Commit changes**, можно написать «Первая версия сайта». Нажмите зелёную кнопку **Commit changes**.

### Шаг 4. Включите GitHub Pages

1. В репозитории откройте вкладку **Settings** (шестерёнка вверху).
2. В меню слева выберите **Pages**.
3. В разделе **Build and deployment**:
   - **Source**: `Deploy from a branch`;
   - **Branch**: выберите `main`, папку `/ (root)`;
   - нажмите **Save**.
4. Подождите 1–3 минуты и обновите страницу настроек. Вверху появится надпись «Your site is live at **https://elenabuteeva.github.io/bonya/**».
5. Откройте ссылку. Если видите ошибку 404 — подождите ещё пару минут.

Ход публикации видно на вкладке **Actions**: жёлтый кружок — идёт публикация, зелёная галочка — готово, красный крестик — ошибка (см. раздел 6).

### Шаг 5. Проверьте превью ссылки

Отправьте ссылку себе в Telegram или WhatsApp. Должна появиться карточка с фото Бони на арбузной подушке и заголовком «Помочь Боне пройти обследования и лечение».

Telegram запоминает превью. Если вы что-то поменяли, а превью старое — отправьте ссылку боту **@WebpageBot** в Telegram, он обновит карточку.

### Как загрузить файл в папку

1. Откройте нужную папку в репозитории (например, `receipts`).
2. **Add file → Upload files**.
3. Перетащите файлы → **Commit changes**.

Файл попадёт именно в ту папку, которая была открыта.

### Как отредактировать файл прямо на GitHub

1. Откройте файл (например, `content.json`).
2. Нажмите значок **карандаша** (Edit this file) справа вверху.
3. Внесите изменения.
4. Нажмите **Commit changes…** → ещё раз **Commit changes**.
5. Через 1–2 минуты изменения появятся на сайте. Если не видно — обновите страницу с очисткой кэша: на компьютере Ctrl+Shift+R (на Mac — Cmd+Shift+R), на телефоне закройте и снова откройте вкладку.

### Как заменить content.json целиком (если его прислал Claude)

Вариант А — через редактор:
1. Откройте `content.json` на GitHub → карандаш.
2. Выделите всё (Ctrl+A / Cmd+A) и удалите.
3. Вставьте новый текст целиком → **Commit changes**.

Вариант Б — загрузкой файла:
1. На главной странице репозитория **Add file → Upload files**.
2. Перетащите новый `content.json` (именно с таким названием) → **Commit changes**. Старый файл заменится.

## 4. Как редактировать content.json

`content.json` — это текстовый файл в формате JSON. Правила простые, но строгие: одна пропущенная запятая — и сайт покажет сообщение об ошибке вместо данных.

### Главные правила

| Правило | Правильно | Неправильно |
|---|---|---|
| Текст — в двойных прямых кавычках | `"Выписка"` | `«Выписка»`, `'Выписка'` |
| Суммы — просто числом | `83993` | `"83 993 ₽"`, `83 993`, `83993₽` |
| Копейки — через точку | `1500.50` | `1500,50` |
| Даты — год-месяц-день | `"2026-09-27"` | `"27.09.2026"` |
| Между элементами — запятая | `{...}, {...}` | `{...} {...}` |
| После последнего элемента — **без** запятой | `[{...}, {...}]` | `[{...}, {...},]` |
| Пустое значение | `""` для текста, `null` для суммы | пропуск |

Кавычки-ёлочки «так» внутри текста можно — они внутри прямых кавычек, например `"клиника «Артемида+»"`. А вот прямую двойную кавычку внутри текста писать нельзя.

### Где проверить файл перед сохранением

Скопируйте весь текст `content.json` и вставьте на сайт **https://jsonlint.com** → кнопка **Validate JSON**. Если написано «Valid JSON» — всё в порядке. Если нет — сайт покажет номер строки с ошибкой.

Сайт Бони тоже подсказывает: если в файле ошибка, вверху страницы появится розовая плашка с описанием, а если не хватает суммы — жёлтая.

### Что за что отвечает

| Раздел в файле | Что это |
|---|---|
| `updated` | Дата обновления данных — показывается в трёх местах на сайте |
| `site_url` | Адрес сайта для кнопки «Поделиться» |
| `goal` | Цель сбора и объяснение, из чего она складывается |
| `donations` | Полученная помощь (из неё считается «Собрано» и «Осталось») |
| `expenses` | Все расходы: оплаченные (`"paid"`) и предстоящие (`"planned"`) |
| `documents` | Выписки, заключения, анализы |
| `news` | Новости «Как Боня сейчас» |
| `texts` | Тексты страницы: заголовок, рассказ о Боне, «Почему я прошу помощи» и т. д. |
| `story` | Блок «Что с ним случилось» |
| `photos` | Какие фотографии где стоят |
| `payments` | Ссылка Т-Банка, реквизиты, криптоадреса |
| `contacts` | Почта и Telegram |

### Как сайт считает суммы

- **Собрано** = сумма всех `amount_rub` в `donations`. Эта цифра только растёт: когда вы оплачиваете лечение или выводите деньги, ничего вычитать не нужно.
- **Осталось** = цель − собрано (не меньше нуля).
- **Процент на шкале** = собрано ÷ цель.
- **Уже оплачено** = сумма всех расходов со статусом `"paid"`.
- **Предстоит** = сумма всех расходов со статусом `"planned"`, у которых указана сумма.

Каждый расход — **одна запись**. Когда плановый расход оплачен, вы не создаёте новую запись, а меняете статус у существующей. Так ничего не посчитается дважды.

Долг по кредитке **не нужно** добавлять как отдельный расход: он уже сидит в оплаченных чеках. Кредитка учитывается только в цели сбора (в тексте `goal.explanation`).

## 5. Готовые примеры: что и как менять

После любого изменения не забывайте поменять дату в самом верху:

```json
"updated": "2026-10-02",
```

### 5.1. Как заменить фотографию

1. Подготовьте фото: JPG, по длинной стороне примерно 1200–1600 пикселей, весом до 400 КБ (можно сжать на https://squoosh.app).
2. Назовите файл латиницей, например `home-2.jpg`.
3. Загрузите его в папку `photos/` на GitHub.
4. В `content.json` в разделе `photos` поменяйте путь:

```json
"photos": {
  "hero": "photos/home-2.jpg",
  "hero_alt": "Боня дома на диване, смотрит в камеру",
```

`hero_alt` — короткое описание фото для незрячих посетителей и на случай, если фото не загрузится.

Где какие фото:

- `hero` — первый экран (сейчас: Боня на арбузной подушке);
- `about` — вырезанный Боня в блоке «Знакомьтесь» (`meet.webp`, запасная копия — `meet.png`);
- `gallery` — три маленьких фото в блоке «Знакомьтесь»;
- `why` — фото в конусе в блоке «Почему я прошу помощи».

**Превью ссылки в мессенджерах** — это отдельный файл `photos/og-image.jpg` (1200 × 630 пикселей). Чтобы поменять его, загрузите новый файл с тем же названием.

### 5.2. Как добавить расход и прикрепить чек

1. Загрузите фото или PDF чека в папку `receipts/`, например `receipts/2026-09-13-chek-1.jpg`. Если чеков по одной оплате несколько — загрузите все.
2. В `content.json` в раздел `expenses` добавьте запись:

```json
"expenses": [
  {
    "status": "paid",
    "date": "2026-09-13",
    "amount": 12500,
    "files": ["receipts/2026-09-13-chek-1.jpg", "receipts/2026-09-13-chek-2.jpg"]
  },
  {
    ...другие записи...
  }
]
```

- `status` — `"paid"`, то есть оплачено;
- `date` — дата оплаты;
- `amount` — сумма числом;
- `files` — список файлов. Если файл один — кнопка на сайте будет «Открыть чек», если несколько — «Чек 1», «Чек 2»;
- можно добавить `"title": "Короткое пояснение"` — оно покажется мелко рядом с суммой. Необязательно.

Если чек не раскрывает состав услуг, а у вас есть детализация от клиники, добавьте её как ещё один файл с подписью:

```json
"files": [
  "receipts/2026-09-19-chek.jpg",
  { "file": "receipts/2026-09-19-detalizaciya.jpg", "label": "Детализация" }
]
```

**Важно про запись на 83 993 ₽.** Сейчас в `expenses` есть одна общая запись «Лечение с 13 по 27 сентября. Чеки добавляю» на 83 993 ₽. Когда будете добавлять отдельные чеки за эти дни, **уменьшайте сумму этой общей записи** на сумму каждого добавленного чека — иначе расходы посчитаются дважды. Когда все чеки будут добавлены, общую запись нужно удалить целиком (вместе с фигурными скобками и запятой перед ней или после неё).

Самый простой путь: пришлите все чеки Claude — он разнесёт их по отдельным записям и пришлёт готовый `content.json`.

Пока файл не загружен на GitHub, кнопка на сайте будет пунктирной с надписью «файл скоро» — посетитель увидит, что чек ещё не выложен.

### 5.3. Как перевести плановый расход в оплаченный

Было (предстоящий расход):

```json
{
  "status": "planned",
  "title": "УЗИ брюшной полости",
  "amount": 1800,
  "source": { "title": "Выписка 27.09", "file": "documents/2026-09-27-vypiska.pdf" }
}
```

Стало (оплачено):

```json
{
  "status": "paid",
  "date": "2026-10-03",
  "title": "УЗИ брюшной полости",
  "amount": 1850,
  "files": ["receipts/2026-10-03-uzi-chek.jpg"]
}
```

Что меняется:

1. `"planned"` → `"paid"`;
2. добавляется `date` — дата оплаты;
3. `amount` — точная сумма по чеку (она могла отличаться от предварительной);
4. добавляется `files` с чеком;
5. `source` можно оставить или удалить — в списке чеков он не показывается.

Запись сама переедет из «Предстоящих расходов» в «Чеки», а суммы «Уже оплачено» и «Предстоит» пересчитаются.

**Как добавить новый предстоящий расход** (вы вписываете сами: что назначено, сколько стоит и из какой выписки):

```json
{
  "status": "planned",
  "title": "ЭхоКГ и ЭКГ сердца",
  "amount": 4500,
  "source": { "title": "Выписка 21.09", "file": "documents/2026-09-21-vypiska.pdf" }
}
```

- если стоимость пока неизвестна — пишите `"amount": null`, на сайте будет «уточняется»;
- у каждого предстоящего расхода есть пометка «предварительно». Если сумма точная (например, клиника выставила счёт), добавьте `"preliminary": false`.

### 5.4. Как добавить полученную помощь

Имена отправителей и выписки из банка **не публикуем**. Достаточно даты и суммы.

**Перевод в рублях:**

```json
"donations": [
  { "date": "2026-09-28", "method": "rub", "amount_rub": 1000 },
  { "date": "2026-09-28", "method": "rub", "amount_rub": 500 }
]
```

Можно вписывать каждый перевод отдельно, а можно одной записью за день:

```json
{ "date": "2026-09-28", "method": "rub", "amount_rub": 7300, "note": "12 переводов за день" }
```

**Перевод в криптовалюте:**

```json
{
  "date": "2026-09-29",
  "method": "crypto",
  "crypto_coin": "USDT",
  "crypto_amount": "55",
  "amount_rub": 4500
}
```

- `crypto_amount` — сколько монет пришло (как есть, в кавычках);
- `amount_rub` — рублёвый эквивалент на день получения (посчитайте по курсу в Bybit). Именно эта цифра прибавится к «Собрано».

**Когда вы потом переводите эту криптовалюту в рубли, новую запись не добавляйте** — эти деньги уже учтены.

Если в `donations` пока нет ни одной записи, там стоят пустые квадратные скобки `[]`. Первая запись вставляется внутрь: `[ { ... } ]`.

### 5.5. Как изменить цель сбора

Цель задаёте вы. Сейчас она не указана (`null`), и на сайте написано «уточняется».

```json
"goal": {
  "amount": 150000,
  "explanation": "Цель складывается из долга по кредитной карте за уже оплаченное лечение Бони (… ₽) и стоимости дальнейших обследований и лечения (… ₽).",

```

- `amount` — сумма цели числом;
- `explanation` — текст под ссылкой «Из чего складывается цель» на первом экране.

Если цель меняется (например, назначили новое обследование), поменяйте `amount` и добавьте объяснение в `changes`:

```json
"changes": [
  { "date": "2026-10-05", "text": "Цель выросла на 20 000 ₽: врач назначил повторный стационар." }
]
```

Новые изменения можно добавлять в начало списка через запятую — сайт сам отсортирует их по дате.

### 5.9. Как добавить криптоадрес из Bybit

1. В приложении Bybit: **Активы (Assets) → Депозит (Deposit)** → выберите монету (например, USDT).
2. Выберите **сеть** (например, TRC20 или TON). Запишите её название точно так, как в Bybit.
3. Скопируйте **адрес**. Если Bybit показывает **Memo / Tag** — скопируйте и его, он обязателен.
4. Впишите в `content.json`:

```json
"crypto": [
  {
    "coin": "USDT",
    "network": "TRON (TRC20)",
    "address": "сюда-вставьте-адрес-из-Bybit",
    "memo": ""
  },
  {
    "coin": "TON",
    "network": "TON",
    "address": "сюда-вставьте-адрес-из-Bybit",
    "memo": "сюда-вставьте-memo"
  }
]
```

- Можно добавить несколько монет — на сайте появятся вкладки.
- QR-код рисуется автоматически прямо из адреса, поэтому он всегда совпадает с адресом.
- Кнопка «Скопировать адрес» станет активной сама.
- Если memo не нужен — оставьте `""`.

**Обязательно проверьте**: после публикации отсканируйте QR-код с сайта телефоном и сравните первые и последние 6 символов с адресом в Bybit. Лучше всего — сделайте пробный перевод небольшой суммы.

### 5.10. Как поменять тексты

Все тексты страницы лежат в разделах `texts` и `story`. Меняйте только то, что внутри кавычек после двоеточия.

Например, блок «Что с ним случилось»:

```json
"story": {
  "clinic": "Сейчас Боня лечится в ветклинике «Артемида+» в Новосибирске.",
  "events": [
    { "when": "13 сентября", "title": "Первые обследования", "text": "…" },
    { "when": "27 сентября", "title": "Снова хуже", "text": "…", "now": true }
  ],
  "confirmed": "что подтверждено анализами",
  "assumed": "что предполагают врачи, но пока не подтверждено",
  "unknown": "что пока неизвестно"
}
```

`"now": true` ставится только у последнего события — оно подсвечивается розовым с пометкой «сейчас».

Важно: подтверждённые результаты и предположения врачей держите раздельно — в `confirmed` и `assumed`.

## 6. Если что-то сломалось

**На сайте розовая плашка «ошибка оформления».** В `content.json` пропущена запятая, кавычка или скобка. Проверьте файл на https://jsonlint.com — там будет номер строки. Чаще всего ошибка стоит прямо перед этой строкой или в последнем изменённом месте.

**На сайте жёлтая плашка «Проверьте content.json».** Где-то нет суммы, или сумма записана текстом (`"1 000"` вместо `1000`), или у расхода неправильный статус.

**Как откатить неудачное изменение:**

1. Откройте `content.json` на GitHub.
2. Нажмите **History** (часы справа вверху).
3. Найдите последнюю хорошую версию → нажмите на неё → **… → View file** → скопируйте текст.
4. Вставьте его в `content.json` через редактор (раздел 3) → **Commit changes**.

**Сайт не обновляется.** Подождите 2 минуты, проверьте вкладку **Actions** (там должна быть зелёная галочка), обновите страницу с очисткой кэша.

**Кнопка «файл скоро» у чека, который вы загрузили.** Название файла в `content.json` не совпадает с настоящим. Сравните буква в букву, включая `.jpg` / `.JPG` / `.pdf` — большие и маленькие буквы различаются.

**Открываете `index.html` на компьютере двойным щелчком — и видите ошибку.** Так и должно быть: браузер не даёт странице читать `content.json` с диска. Смотрите сайт по ссылке GitHub Pages.

**Шрифты выглядят проще, чем в макете.** Шрифты Unbounded и Onest подгружаются с Google Fonts. Если Google Fonts недоступен, сайт автоматически использует системные шрифты — всё остаётся читаемым.

## 8. Автоматический учёт криптовалюты через Bybit — на будущее

Сейчас поступления криптовалюты вносятся **вручную**, и сайт нигде не пишет, что они обновляются автоматически. Это правильно для начала. Если позже захочется автоматики, вот как это устроено.

### Чего нельзя делать

- **Нельзя подключать API Bybit прямо на сайте.** Всё, что лежит в репозитории и на странице, видно любому человеку. Ключ API, размещённый в `app.js` или `content.json`, сразу станет публичным.
- Нельзя создавать ключ с правами на вывод или торговлю.

### Как это делается безопасно

Нужен маленький скрипт, который работает **не в браузере посетителя**, а на отдельной машине, где ключ спрятан:

1. Раз в час (или раз в день) скрипт обращается к API Bybit с ключом «только чтение».
2. Получает список входящих депозитов (метод Bybit V5 `GET /v5/asset/deposit/query-record`).
3. Записывает в репозиторий отдельный файл, например `crypto-deposits.json`: дата, монета, сумма, хеш транзакции — без каких-либо имён.
4. Сайт читает этот файл так же, как `content.json`.

Где может работать скрипт:

- **GitHub Actions** — бесплатное расписание прямо в вашем репозитории. Ключ хранится в **Settings → Secrets and variables → Actions** и никому не виден. Минус: серверы GitHub находятся в основном в США, а Bybit ограничивает доступ из некоторых стран, в том числе из США, — запросы могут не пройти. Это надо проверить до того, как на это рассчитывать.
- **Cloudflare Workers** или небольшой облачный сервер в стране, откуда Bybit доступен. Ключ хранится в секретах сервиса.
- **Ваш компьютер** — скрипт по расписанию, который сам загружает обновлённый файл на GitHub.

### Что проверить в аккаунте Bybit

1. **Доступен ли API для вашего аккаунта** (зависит от страны и уровня верификации) — раздел **API** в настройках профиля.
2. **Можно ли создать ключ «только чтение» (Read-Only)** с доступом к разделу активов/кошелька — без торговли и вывода.
3. **Ограничение по IP.** Bybit предлагает привязать ключ к IP-адресу. Ключи без привязки к IP обычно действуют ограниченный срок (например, 3 месяца), потом их нужно перевыпускать. У GitHub Actions IP-адреса меняются, поэтому привязать их не получится.
4. **Отдельный субаккаунт для сбора.** Удобно завести субаккаунт только для пожертвований: тогда скрипт видит только их, а не ваши личные операции.
5. **Внутренние переводы Bybit** (между пользователями Bybit) — это отдельный список, а не депозиты из блокчейна; их тоже нужно учитывать.

### Что останется делать вручную

- **Рублёвый эквивалент.** API отдаёт суммы в монетах. Курс на день получения нужно либо брать из отдельного источника курсов, либо вписывать вручную.
- **Проверка, что это пожертвование**, а не ваш собственный перевод.

Когда будете готовы — скажите Claude: «Давай подключим автоматический учёт Bybit». Скрипт и настройку можно сделать отдельно.
